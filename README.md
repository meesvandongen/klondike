# Solitaire Suite

Six classic card games — **Klondike**, **FreeCell**, **Spider** (1-suit), **TriPeaks**, **Pyramid** and **Hearts** — built with [MyGo](https://github.com/egoist/mygo) (Go) + SolidJS, styled after the Windows Vista native editions: deep felt background, classic playing-card layout, native window menu, and shared card scale.

Each variant ships as its own app (Klondike.exe / FreeCell.app / etc.) with its own icon and identifier, all from one small Go program, and the whole suite is also published as a single static web bundle.

## Variants

| Variant   | Mechanic           | Notes                                                   |
|-----------|--------------------|---------------------------------------------------------|
| Klondike  | Drag, click-to-act | Guaranteed-winnable deals via built-in solver           |
| FreeCell  | Drag, click-to-act | 4 free cells, near-100% solvable random deals           |
| Spider    | Drag, click-to-act | 1-suit (8 sequences of Spades), stock deals 10 at once  |
| TriPeaks  | Click only         | Chain consecutive ranks (A↔K wraps) for bonus points    |
| Pyramid   | Click only         | Pair cards summing to 13; 3 stock recycles              |
| Hearts    | Click only         | Trick-taking against 3 AI opponents; avoid hearts + Q♠  |

## Shared base

The frontend lives entirely under `src/`. A `src/shared/` directory provides the reusable infrastructure used by every variant:

- `deck.ts`        — suits, ranks, glyphs, deck builder
- `Card.tsx`       — Solid card component + SVG face-card art
- `drag.ts`        — pointer-capture-based drag/drop manager (used by drag-based games)
- `Modal.tsx`      — Vista-style dialog
- `menu.ts`        — native menu listener + dispatch, and the calls that keep the menu's check items in sync
- `mygo.ts`        — typed client of the Go side, generated by `mygo generate` (do not edit)
- `hotkeys.ts`     — `F2`, `Ctrl/Cmd+Z`, `H`, `Ctrl/Cmd+A` mapping + Escape/Enter modal handling
- `stats.ts`       — per-game localStorage stats
- `Status.tsx`     — status-bar (score / time / moves)
- `Overlay.tsx`    — "dealing…" overlay
- `styles.css`     — shared Vista board / card / modal / status styling
- `utils.ts`       — `formatTime`, `cssVarPx`, `shuffle`, `clone`

Each variant directory (`src/<game>/`) contains only the game-specific bits:

- `game.ts`  — rules engine (state, moves, win, undo, hint, auto-complete)
- `solver.ts` — *Klondike only*, used for winnable-deal verification
- `ai.ts` — *Hearts only*, passing + play heuristics for the bots
- `main.tsx` — wires rendering, drag/click, dialogs and menu to the engine
- `index.html`, `styles.css` — board layout overrides

## Desktop shell

The desktop apps are a single Go program, `main.go`, built with
[MyGo](https://github.com/egoist/mygo): each window shows the game's page
of the Vite build in the system webview (WKWebView, WebView2 or
WebKitGTK), so an app is a single ~10 MB executable with no bundled
browser and no cgo.

- The native menu (Game / Edit / View / Help) is defined once in
  `main.go` and sends a typed `menu` event (`{ id, checked? }`) to the
  page; each variant decides how to handle the action (or whether to
  ignore it).
- The page calls back into Go through the bound `Menu` service
  (`Menu.syncDrawMode`, `Menu.syncAutoComplete`) to keep the menu's check
  items in step with the Options dialog.
- `mygo.config.ts` describes the app. The game is chosen by the
  `SOLITAIRE_GAME` environment variable, which sets the app's name,
  identifier and icon; `main.go` maps the app name back to the game's
  page, window size and menu items. `scripts/app.mjs` sets the variable
  so the package scripts work in every shell.

## Prerequisites

- Node.js 22.18+ (pnpm via `corepack enable`)
- Go 1.27.3+ (the `mygo` CLI itself comes from the `mygo-cli` npm package)
- On Linux, GTK 3 and WebKitGTK 4.1 (`libwebkit2gtk-4.1-0` on Debian/Ubuntu);
  on Windows 10, the WebView2 Runtime (Windows 11 includes it).
  `pnpm exec mygo doctor` checks the machine.

## Running a variant locally

Desktop (MyGo shell, with live reload of both the Go code and the page):

```bash
pnpm install

pnpm run app:dev                # default = Klondike
pnpm run app:dev:freecell
pnpm run app:dev:spider
pnpm run app:dev:tripeaks
pnpm run app:dev:pyramid
pnpm run app:dev:hearts
```

Browser only (Vite dev server, opens at `localhost:1420`):

```bash
pnpm run dev
# then open /klondike/, /freecell/, /spider/, /tripeaks/,
#                /pyramid/, /hearts/ or just / for the landing page.
```

## Building executables

```bash
pnpm run app:build              # Klondike
pnpm run app:build:freecell
pnpm run app:build:spider
pnpm run app:build:tripeaks
pnpm run app:build:pyramid
pnpm run app:build:hearts
```

Each command builds the frontend, embeds it into the Go executable and
packages it for this machine in `build/<os>-<arch>/`:

- macOS: `<Variant>.app` and `<variant>-<version>-<arch>.dmg`
- Windows: `<Variant>.exe` and `<variant>-setup-<version>-amd64.exe`
- Linux: the executable, `.deb`, `.rpm`, a `.tar.gz` with `install.sh`, and a PKGBUILD

MyGo needs no cgo, so any machine can compile for any platform; pass
`mygo build` flags after the game name:

```bash
node scripts/app.mjs build hearts -platform darwin/universal,windows/amd64,linux/amd64
```

(Run it through `pnpm exec` so `mygo` is on the `PATH`. macOS disk images
still need a Mac.)

After changing the bound methods or events in `main.go`, regenerate the
typed client with `pnpm run app:generate` (`app:dev` and `app:build` do
this automatically). It is committed so the web build needs no Go.

## Building the web bundle

```bash
pnpm run build
```

Writes a static site to `dist/` — open `dist/index.html` for the
landing page, or any `dist/<game>/index.html` directly.

### Deploying to Cloudflare

`wrangler.toml` at the repo root configures the site for
**Cloudflare Workers Static Assets**: it points wrangler at
`./dist` and uses default HTML handling (so `/hearts/` resolves to
`/hearts/index.html` without any rewriting).

For a one-off deploy from your machine:

```bash
pnpm install
pnpm run build
pnpm exec wrangler deploy        # or: pnpm run cf:deploy
```

For continuous deployment via Cloudflare's git integration
(*Workers & Pages → Create → Workers → Connect to git*), set:

- **Build command:** `pnpm run build`
- **Deploy command:** `pnpm exec wrangler deploy`
- **Root directory:** *(leave blank — project is at repo root)*

The build pipeline picks up `wrangler.toml` automatically; the
"root directory not found" error in the Cloudflare build log
specifically means that setting is pointed at a path that doesn't
exist in the repo.

## Icons

The icons under `icons/<game>/icon.png` are generated from
`scripts/make_icons.py`, which renders Vista-style felt-and-cards
artwork as one 1024×1024 PNG per game; `mygo build` derives the
`.icns`, `.ico` and Linux icon sizes from it. Re-run after editing the
script:

```bash
python3 scripts/make_icons.py
```

## CI

`.github/workflows/build.yml` runs three pipelines:

1. **Build** — a **(platform × variant)** matrix produces a zipped
   universal `.app` for macOS, an installer `.exe` for Windows and
   `.deb` / `.rpm` / `.tar.gz` packages for Linux, for each of the six
   games (18 parallel jobs). Artifacts are uploaded individually.
2. **Web bundle** — a single job lints, runs the Go tests, checks that
   the generated client is up to date, runs `pnpm run build` and uploads
   the `dist/` tree as the `solitaire-web` artifact.
3. **Release** — on a `v*` tag push, every desktop artifact is
   attached to the matching GitHub Release.
